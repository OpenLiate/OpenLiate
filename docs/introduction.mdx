## The Mathematical Inspiration: The LIATE Rule

In calculus, the **LIATE Rule** is the universal mnemonic used to break down complex mathematical integration by parts:

> *"Don't build AI agents. Integrate by parts."*

Just as the LIATE rule breaks down complex equations into solvable components, OpenLiate decomposes agent engineering into 5 manageable layers:

| Calculus LIATE Rule (Problem Decomposition) | OpenLiate LIATE Architecture (Agent Decomposition) |
| :--- | :--- |
| **`L`** — **Logarithmic** | **`[L]`** — **Large Models Layer** (Sarvam AI 105B/2B, Ollama, Cloud LLMs) |
| **`I`** — **Inverse Trigonometric** | **`[I]`** — **Integration & Memory Layer** (Knowledge, Sessions, State, Postgres) |
| **`A`** — **Algebraic** | **`[A]`** — **Agent Harness Layer** (ReAct Reasoning Loop, maxSteps guardrails) |
| **`T`** — **Trigonometric** | **`[T]`** — **Tools & MCP Layer** (Aadhaar & PAN verification, Stdio/HTTP MCP) |
| **`E`** — **Exponential** | **`[E]`** — **Environment & Sandbox Layer** (Secrets, Safe `$VAR`, Guardrails) |

## NVIDIA 5-Element Alignment

On stage, **NVIDIA CEO Jensen Huang** demonstrated that an AI Agent is fundamentally comprised of 5 foundational elements: **Model, Knowledge, Harness, Tools, and Sandbox**. 

OpenLiate provides a direct, 1-to-1 implementation of this architecture in **5 lines of declarative JSON**:

```json agent.json
{
  "L": "sarvam/sarvam-105b",                     // [L] Model: Sovereign LLMs & local silicon
  "I": { "memory": "sessions/my-agent" },        // [I] Knowledge: Session history & database state
  "A": { "name": "analyst", "maxSteps": 10 },    // [A] Harness: ReAct autonomous loop & intent
  "T": {                                         // [T] Tools: Model Context Protocol (MCP v2)
    "fetch": { "command": "uvx", "args": ["mcp-server-fetch"], "tools": ["*"] }
  },
  "E": { "SARVAM_API_KEY": "$SARVAM_API_KEY" }   // [E] Sandbox: Secret isolation & guardrails
}
```
